# Данные проекта

- `plants.jsonl` — небольшой демонстрационный корпус из четырёх записей, достаточный для проверки загрузчика, BM25, RAG и интерфейса.
- `benchmark.json` — smoke-набор с тремя поисковыми вопросами и одним вопросом, на который система должна воздержаться от ответа.

**Важно:** записи в `plants.jsonl` имеют `record_status: demo_unverified`, не содержат ссылок на внешние первоисточники и требуют ботанической фактологической и лицензионной проверки. Это не готовая научная база, не подтверждение безопасности растения и не медицинский справочник. Перед публичным запуском замените демонстрационные тексты проверенными материалами, сохраните их происхождение и условия использования. Не подменяйте `source_url` вымышленными ссылками.

Формат — JSONL: одна запись на строку, UTF-8. Обязательные поля: `document_id`, `plant_name`, `content`. См. `docs/retrieval/corpus-spec.md`.


## Проверка корпуса

Из корня репозитория выполните:

```bash
python -m backend.scripts.validate_corpus
python -m backend.scripts.validate_corpus --strict
```

Обычный режим показывает число документов/chunks, статусы записей и пробелы в provenance. `--strict` завершается с ненулевым кодом, если хотя бы одна запись не имеет `record_status=reviewed` или `source_url`. Для текущих четырёх демонстрационных строк strict-режим намеренно не проходит.
