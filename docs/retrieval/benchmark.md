# Benchmark поиска и RAG

**Статус:** реализован runner и небольшой smoke-набор; полного экспертно размеченного benchmark пока нет.

## 1. Цель

Проверить, находит ли BM25 правильные материалы, не ухудшается ли ранжирование после изменений chunking/нормализации/параметров и корректно ли система воздерживается от ответа при отсутствии материалов.

## 2. Формат тестового случая

`data/benchmark.json` содержит `query_id`, `query`, `expected_doc_ids` и `should_abstain`. Для полноценного набора добавьте также `intent`, `notes`, `expected_answer` и оценки релевантности, согласованные проверяющими.

## 3. Текущий smoke-набор

В репозитории сейчас 4 сценария:

| ID | Тип | Запрос | Эталон |
|---|---|---|---|
| S01 | поиск вида/механизма | венерина мухоловка ловушка створки | `plant-dionaea-001` |
| S02 | поиск признаков | росянка липкие капли насекомые | `plant-drosera-001` |
| S03 | поиск типа ловушки | непентес кувшинчатые ловушки | `plant-nepenthes-001` |
| S04 | ловушка / отказ | какое комнатное растение лечит диабет | нет релевантного документа, ожидается abstain |

Это тестовые запросы, подобранные под демонстрационные записи. Они не доказывают качество на новых пользовательских вопросах.

## 4. Полный учебный набор

Для контрольной точки расширить корпус до 30 документов и подготовить 10 обычных вопросов с ответом в корпусе и 5 вопросов-ловушек без достаточной информации. Для каждого обычного вопроса человек указывает релевантные ID (в методичке рекомендовано не менее трёх, где это применимо) и эталонный ответ. Вопросы-ловушки должны проверять отсутствие сведений, а не неоднозначность формулировки.

## 5. Запуск

```bash
python -m backend.scripts.run_benchmark
```

Параметры: `--benchmark PATH`, `--output PATH`, `--k 5`. По умолчанию output — `.data-local/benchmark-last.json`. Скрипт фиксирует корпус и retrieval statistics, per-query ranking, Recall@k, Precision@k, reciprocal rank, MRR и корректность отказа для вопросов без эталонных документов.

## 6. Текущий результат smoke benchmark

Последний зафиксированный прогон хранится в `benchmark-results-smoke.json`:

| Метрика | Результат |
|---|---:|
| Корпус | 4 документа / 4 chunks |
| Recall@5 (3 поисковых вопроса) | 1.00 |
| Precision@5 (3 поисковых вопроса) | 0.20 |
| MRR@5 | 1.00 |
| Correct abstention rate (1 trap) | 1.00 |

Precision@5 считается по знаменателю k=5, даже если система вернула меньше пяти уникальных документов. Небольшой корпус, крайне малое число запросов и учебные тексты не позволяют переносить эти значения на production.

## 7. Метрики и ручная оценка

- **Recall@k:** доля релевантных документов из эталона, найденных в top-k.
- **Precision@k:** доля релевантных документов в top-k.
- **MRR@k:** средний обратный ранг первого релевантного документа.
- **Accuracy ответов:** доля полностью корректных ответов по человеческой проверке.
- **Correct abstention rate:** доля правильных отказов на вопросах-ловушках.
- **Groundedness/citation correctness:** вручную оцениваются подтверждение каждого фактического утверждения и соответствие ссылки источнику, реально переданному в модель.

## 8. Воспроизводимость

Фиксируйте версии корпуса, BM25 параметров, `MIN_BM25_SCORE`, chunk size/overlap, prompt и выбранной LLM. Меняйте одну настройку за раз. Результаты с разным корпусом не сравнивайте без явного указания.
