# Рабочий процесс AI-агента

## 1. Понять задачу и SDD

- Найди требование в `docs/product/requirements.md`, пользовательский сценарий и владельцев затронутой области.
- Учитывай текущие фактические возможности, перечисленные в `docs/ai/PROJECT_CONTEXT.md`.
- Если меняется API, corpus schema, BM25 нормализация, tool policy, модель или UI-сценарий — сначала обнови связанный документ/ADR.

## 2. Исследовать репозиторий

- Прочитай `AGENTS.md`, PROJECT_CONTEXT и Definition of Done.
- Изучи фактический код, зависимости и тесты; не предполагай, что документация обязательно свежее кода.
- Проверь status Git, если архив является Git checkout; не перезаписывай чужие изменения.

## 3. Реализовать

- Frontend — существующий HTML/CSS/JS, не добавляй фреймворк без необходимости.
- Backend — FastAPI, бизнес-логика отделена в `corpus.py`, `retrieval.py`, `service.py`, `llm.py`.
- BM25: сохраняй воспроизводимость формулы презентации и измеряй изменения benchmark.
- RAG: source metadata должна проходить через retrieval, prompt и API без потери связи.
- Agent tools: только allowlist, ограниченные аргументы, ограничение количества вызовов и контекста.
- Никаких секретов в Git; `.env` должен оставаться локальным.

## 4. Проверить

```bash
python -m compileall -q backend
python -m pytest -q
python -m backend.scripts.run_benchmark
node --check js/app.js
```

Запускай Node check, если Node установлен. Живые вызовы LLM/Pl@ntNet указывай как проверенные только после фактического запуска с credentials.

## 5. Обновить документацию

Обновляй README, SDD, API contract, corpus spec, retrieval benchmark и интерфейсные документы при изменении поведения. Если live-provider integration не выполнялась, обозначай её как реализованную, но не проверенную в конкретной среде.

## 6. Отчёт

Сообщи изменённые файлы, тестовые команды/результаты, оставшиеся ограничения и ближайший шаг. Не заявляй о завершении функций, требующих конфигурации или данных, которых не было.
