# Требования к продукту и критерии приёмки

**Документ:** SDD / Product requirements  
**Версия:** 1.1  
**Статус:** целевой MVP с реализованным BM25/RAG backend и интерфейсной интеграцией.

## 1. Границы продукта

«Бестиарий растений» — образовательный веб-справочник. Пользователь задаёт вопрос или ищет вид; система выполняет BM25 по корпусу, при включённой LLM формирует ответ на основе найденных фрагментов и возвращает источники. В опциональном сценарии фото отправляется в Pl@ntNet, кандидат выбирается пользователем, а информация о нём ищется во внутреннем корпусе.

Проект не является медицинским сервисом, инструментом определения съедобности или гарантированным ботаническим идентификатором.

| ID | Требование | Приоритет | Статус / критерий приёмки |
|---|---|---|---|
| FR-01 | Ввод текстового запроса | Must | Реализовано; Enter и кнопка отправляют запрос |
| FR-02 | Отклонение пустого запроса | Must | Реализовано; backend валидирует 1–1000 символов после trim |
| FR-03 | Поиск по названию/вопросу | Must | Реализовано; `/api/v1/search` и BM25 |
| FR-04 | Отображение найденных результатов | Must | Реализовано в сообщении/списке источников |
| FR-05 | Ответ по найденному контексту | Must | Реализовано; при настроенной LLM вызов выполняется через RAG service |
| FR-06 | Ссылки на источники | Must | Реализовано; метаданные возвращает backend, отсутствующие URL не создаются |
| FR-07 | Отказ при недостатке сведений | Must | Реализовано; `status=insufficient_data` при пустой выдаче |
| FR-08 | Состояние загрузки | Must | Реализовано; текст ожидания и блокировка повторной отправки |
| FR-09 | Понятная обработка ошибок | Must | Реализовано на frontend/API; внешние детали и stack trace скрыты |
| FR-10 | Базовая информация о растении | Should | Реализовано через профиль и source metadata; зависит от наполненности корпуса |
| FR-11 | Безопасное поведение | Must | Реализовано как prompt/ограничение продукта; дополнительно требуется regression-тестирование реальной LLM |
| FR-12 | Повторный запрос без перезагрузки | Must | Реализовано; чаты/сообщения остаются в интерфейсе |
| FR-13 | Дополнительный поиск по запросу LLM | Should | Реализовано через allowlisted tools, budget 5 по умолчанию / 10 максимум |
| FR-14 | Выбор локальной или API LLM | Must | Реализовано конфигурацией `.env`: `none`, `ollama`, `openai_compatible` |
| FR-15 | Распознавание растения по фото | Could | Реализован optional endpoint/UI; требуется `PLANTNET_API_KEY`, ручное подтверждение кандидата |
| FR-16 | Локальная история чатов | Should | Реализовано в `localStorage`; серверной синхронизации нет |

## 3. Нефункциональные требования

| ID | Требование | Критерий |
|---|---|---|
| NFR-01 | Читаемость и адаптивность | Сохранён текущий HTML/CSS; на мобильной ширине элементы источников и фото не должны перекрывать композер |
| NFR-02 | Воспроизводимый запуск | Установка по `requirements.txt`, запуск через `uvicorn backend.app.main:app` |
| NFR-03 | Трассируемость ответа | Каждый chunk сохраняет `document_id`, `chunk_id`, source title/URL и временный source ref |
| NFR-04 | Разделение секретов | Ключи читаются только backend из `.env`; `/api/v1/config` не возвращает secrets |
| NFR-05 | Обработка отказов | Пустая выдача, недоступная LLM и отсутствие PlantNet key не приводят к фиктивному ответу |
| NFR-06 | Поддерживаемость | Архитектура, API, данные и запуск документированы в `docs/` |
| NFR-07 | Защита Agentic RAG | Только зарегистрированные tools, ограниченные число вызовов, chunks и контекст |
| NFR-08 | Обработка загрузки | Только JPEG/PNG и ограничение размера upload |

## 4. Не входит в текущую реализацию

- собственная обученная модель классификации растений;
- dense/vector retrieval и hybrid fusion с BM25;
- полноценная серверная БД, пользовательские аккаунты, авторизация и синхронизация истории;
- модерация/научная экспертиза всего корпуса;
- streaming ответа и отмена генерации;
- гарантированно полная база видов;
- автоматическое определение съедобности/токсичности.
