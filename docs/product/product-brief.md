# Product brief — Бестиарий растений

**Версия:** 1.1  
**Статус:** продуктовая спецификация работающего прототипа с подключённым BM25/RAG.

## 1. Краткое описание

«Бестиарий растений» — веб-справочник для поиска и изучения необычных реальных видов растений. Пользователь задаёт вопрос обычным языком или ищет вид по названию. Система находит фрагменты корпуса при помощи BM25, а настроенная LLM формирует краткий ответ по найденному контексту с указанием источников. При выключенной LLM можно использовать поиск и просматривать найденные выдержки.

Дополнительный сценарий: пользователь загружает фото, получает варианты вида от Pl@ntNet, вручную выбирает кандидат и ищет сведения о нём во внутреннем корпусе.

## 2. Проблема пользователя

Сведения о растениях разбросаны по источникам и отличаются по полноте и качеству. Справочник с естественно-языковым поиском, кратким grounded-ответом и трассируемыми источниками должен упростить первичное знакомство с видом. Это продуктовая гипотеза, которую нужно проверить на пользователях.

## 3. Аудитория

- учащиеся и студенты;
- любознательные пользователи, интересующиеся необычными растениями;
- пользователи, которым удобнее задавать вопрос, чем искать нужный термин.

Система не предназначена для экспертной научной работы, медицинской консультации, определения съедобности или гарантированного распознавания вида.

## 4. Основная ценность

Пользователь получает компактный ответ с привязкой к реальным материалам корпуса и может перейти к исходному источнику. Если база не содержит нужных сведений, система сообщает об этом, а не достраивает ответ из памяти модели.

## 5. Текущий основной сценарий

1. Пользователь открывает чат.
2. Формулирует вопрос/название.
3. Frontend вызывает `/api/v1/ask`.
4. Backend выполняет BM25 по чанкам выбранного корпуса: JSONL для smoke/demo или SQLite (`plants`, `documents`, `plant_descriptions`, `plant_uses`, `plant_compounds`, `habitats`) для основного проекта.
5. Если LLM настроена, ей передаётся вопрос и найденный контекст; в agentic режиме модель может запросить дополнительный контекст через ограниченные tools.
6. UI показывает ответ, режим retrieval/generation и источники.
7. При недостатке данных отображается отказ; пользователь может уточнить запрос.

## 6. Функции MVP и состояние

- BM25 самостоятельной реализации — реализован.
- JSONL/SQLite corpus loader и chunking реализованы; JSONL seed из 4 записей помечен как demo_unverified. SQLite требует реальной DB с наполненными строками и источниками.
- RAG — реализован; работающая генерация требует выбора и настройки модели/API.
- Agentic RAG — реализован; живой вызов зависит от tool-calling поддержки модели.
- Фотоидентификация — реализован optional proxy Pl@ntNet; требуется ключ и ручной выбор.
- Интерфейсный API integration — реализована; чат localStorage.

## 7. Не входит в MVP

- обучение своей модели зрения или LLM;
- гарантированная полнота корпуса;
- dense/vector/hybrid retrieval;
- серверная авторизация, синхронизация чатов и личные коллекции;
- медицинские рекомендации и определение пригодности к употреблению.

## 8. Принципы

- проверяемость и реальные источники;
- явное обозначение demo/unverified материалов;
- воздержание от ответа при недостаточном контексте;
- ограничение агентных итераций и размера контекста;
- пользовательское подтверждение результата фотоидентификации;
- сохранение исходного дизайна и минимальная сложность стека.
