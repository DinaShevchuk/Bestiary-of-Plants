# Спецификация интерфейса

**Источник визуального решения:** существующий HTML/CSS-прототип; локальный редизайн не выполнялся.  
**Статус:** основной чат интегрирован с FastAPI; изображение распознаётся опционально через Pl@ntNet.

## 1. Основные области экрана

1. Левая панель: логотип Flora, тема, новый чат, список локальной истории.
2. Область сообщений: вопрос пользователя, ответ/выдержки, источники и варианты распознавания.
3. Композер: поле вопроса, загрузка фотографии, отправка.
4. Строка статуса: подключение backend, BM25, тип LLM, доступность PlantNet.

## 2. Текстовый запрос

- Отправка по Enter и кнопке.
- Пустой/пробельный запрос не отправляется.
- Во время запроса блокируется повторная отправка и отображается сообщение ожидания.
- При успехе показывается ответ, режим генерации/поиска и фактический список источников.
- При отсутствии контекста система возвращает `insufficient_data`.
- При технической ошибке пользователь видит сообщение о недоступности сервера; stack trace не показывается.

## 3. Источники

Каждый источник может показывать source ref, название растения, научное имя, название публикации, статус `demo_unverified`, фрагмент и URL. URL создаётся только из реально присутствующего HTTP(S) `source_url`; отсутствующая ссылка не заменяется фиктивной.

## 4. Фото

- Кнопка камеры открывает выбор файла.
- Разрешены JPEG/PNG; backend ограничивает размер по умолчанию 10 МБ.
- До отправки показывается превью; пользователь может отменить выбор.
- После вызова API показывается до пяти кандидатов с научным именем и score внешнего сервиса.
- Пользователь нажимает «Искать сведения об этом растении», чтобы подтвердить кандидата и запустить обычный `/ask`.
- UI предупреждает, что распознавание предварительное; score не называется вероятностью.
- Если ключ Pl@ntNet не настроен, интерфейс показывает ошибку конфигурации без фиктивного результата.

## 5. История чатов

Чаты хранятся в `localStorage` текущего браузера, ограничиваются последними 50 локальными чатами. Изображения не сохраняются в истории; сохраняются только текст, результаты-кандидаты и источники. Синхронизации между устройствами и учётных записей нет.

## 6. Доступность и адаптивность

- Кнопки имеют доступные подписи; списку чатов добавлена клавиатурная активация.
- Область сообщений помечена `aria-live`.
- Стили источников и фото-кандидатов адаптируются на мобильной ширине.
- Ошибки и ограничения отображаются текстом, а не только цветом.

## 7. Известные ограничения UI

- Нет streaming-вывода токенов: ответ появляется после завершения запроса к backend.
- Нет кнопки остановки/отмены запроса.
- Реальная аутентификация не реализована; login/register остаются демонстрационными.
