# Фотоидентификация растений

**Статус:** интеграционный endpoint и UI-поток реализованы; внешний вызов требует ключа Pl@ntNet.

## 1. Решение

Собственная модель классификации и отдельное обучение не требуются для первой версии. Backend делегирует идентификацию специализированному Pl@ntNet API, который принимает одну или несколько фотографий одного и того же растения и возвращает ранжированный список вероятных видов. См. официальную [документацию Pl@ntNet API](https://my.plantnet.org/doc/api/identify).

## 2. Поток пользователя

1. Пользователь выбирает изображение в текущем интерфейсе Flora.
2. Frontend проверяет MIME type и показывает предпросмотр.
3. Файл отправляется как `multipart/form-data` в `POST /api/v1/identify`.
4. Backend проверяет ключ, MIME type, размер и сигнатуру JPEG/PNG, затем проксирует запрос на Pl@ntNet `/v2/identify/all`.
5. UI показывает до пяти кандидатов, научные/обычные имена и score внешнего сервиса.
6. Пользователь вручную выбирает наиболее вероятный вариант.
7. Выбранное имя передаётся в `/api/v1/ask`; поиск знаний выполняется только по внутреннему корпусу проекта.

## 3. Конфигурация и ограничения

```dotenv
PLANTNET_API_KEY=<secret>
PLANTNET_API_URL=https://my-api.plantnet.org/v2/identify/all
MAX_UPLOAD_BYTES=10485760
```

Принимаются JPEG/PNG с проверкой сигнатуры файла; лимит приложения по умолчанию 10 MiB. Pl@ntNet документирует до пяти снимков одного растения на запрос и MIME type JPEG/PNG; текущий UI отправляет один снимок за раз. Для использования API нужен отдельный ключ и соблюдение квот/условий провайдера.

## 4. Достоверность

Score Pl@ntNet в диапазоне 0–1 показывается как «оценка сервиса», а не гарантия верного определения и не калиброванная вероятность для приложения. Пользователь подтверждает кандидата вручную. Одного снимка может быть недостаточно для определения вида; не использовать результат для решения о съедобности или безопасности растения.

## 5. Границы

- Внешний вызов не запускается, если `PLANTNET_API_KEY` отсутствует — API возвращает `503`.
- Фото не передаётся в LLM и не используется для обучения локальной модели.
- Текстовый вопрос по выбранному виду отвечает на основе внутреннего корпуса; если профиль отсутствует, RAG должен сообщить об отсутствии данных.
- Автоматическое открытие Google Lens / scraping Google Images не применяется.
