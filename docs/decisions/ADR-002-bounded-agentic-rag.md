# ADR-002: Ограниченный Agentic RAG через allowlist-инструменты

- **Статус:** принято; реализовано в базовом варианте.
- **Контекст:** первоначальный RAG-запрос может не содержать всех сведений для ответа. Модель должна иметь возможность запросить дополнительные фрагменты, но не получать произвольный доступ к БД, файловой системе или сети.
- **Решение:** backend предоставляет `search_plant_knowledge` и `get_plant_profile`. Все аргументы валидируются сервером. По умолчанию допускается до 5 дополнительных tool calls, hard cap — 10; уникальный контекст и его размер ограничиваются независимо. Повторы фрагментов не расширяют контекст.
- **Последствия:** модель может делать последовательный поиск, а backend сохраняет контроль бюджета и источников. Совместимость реального tool calling зависит от выбранной модели; fake-LLM тесты не доказывают работу внешнего endpoint.
- **Отказ/альтернатива:** `AGENTIC_ENABLED=false` выключает цикл; остаётся обычный RAG или retrieval-only режим.
