# ADR-001: Область MVP и границы проекта

- **Статус:** принято; обновлено после реализации BM25/RAG
- **Дата исходного решения:** 2026-10-10
- **Последнее уточнение:** 2026-11-20

## Контекст

Команда разрабатывает учебный проект «Бестиарий растений». Исходная спецификация определяла веб-справочник, документный корпус, поиск BM25 и ответ LLM по найденному контексту. В текущем исходном архиве был статический HTML/CSS/JS-прототип без работающего поискового backend.

## Решение

1. Проект предназначен для справочного ознакомления с реальными растениями; вымышленные виды требуют отдельного пересмотра scope.
2. Основной сценарий: вопрос → BM25 retrieval → контекст → LLM (если настроена) → ответ + источники.
3. BM25 реализуется самостоятельно по формуле учебной презентации с параметрами по умолчанию `k1=1.2`, `b=0.75`.
4. RAG использует BM25 chunks как retrieval layer. Dense embeddings/hybrid fusion не обязательны для первой работающей реализации и пока не внедрены.
5. LLM подключается через единый OpenAI-compatible клиент; локальная конфигурация — Ollama, удалённая — совместимый API.
6. Agentic RAG допускает только два зарегистрированных search tools, лимит по умолчанию 5 вызовов и абсолютный предел 10, плюс отдельный лимит уникальных фрагментов/символов контекста.
7. Фотоидентификация допускается как необязательная интеграция стороннего сервиса Pl@ntNet; собственное обучение компьютерного зрения в MVP не требуется. Кандидат должен подтвердить пользователь.
8. Не выдавать медицинские советы или инструкции по употреблению/самолечению; источник и фактологическая проверка обязательны для safety-sensitive фактов.

## Последствия

- Добавлен Python/FastAPI backend в существующую структуру без frontend framework migration.
- JSONL или SQLite corpus adapter и chunker формируют BM25 index при старте backend; Excel импортируется в таблицу `plants` отдельной командой.
- В текущем репозитории четыре учебных записи `demo_unverified`; они демонстрируют работу кода, но не могут считаться верифицированной базой.
- Интеграции с живой LLM/Pl@ntNet требуют конфигурации и не проверялись в сборочной среде без ключей/сервиса.
- Серверная история/авторизация, dense retrieval, full benchmark и проверенный корпус остаются отдельными задачами.

## Альтернативы

- Готовый поисковый движок вместо собственной BM25-реализации: отклонено для учебного baseline, поскольку презентация требует собственный индекс.
- Собственное обучение image classifier: отклонено для MVP из-за потребности в размеченном датасете; использован внешний plant identification API.
- Автоматизация Google Lens/Google Images: отклонено из-за отсутствия стабильного интеграционного API и несоответствия принципу надёжного серверного контракта.
